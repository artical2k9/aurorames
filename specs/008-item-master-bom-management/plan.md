# Implementation Plan: Item Master & BOM Management

**Branch**: `008-item-master-bom-management` | **Date**: 2026-05-25 | **Spec**: [spec.md](spec.md)

**Input**: Jira Epic MES-8 — Item Master & BOM Management (P2 Epic)

---

## Summary

Scaffold `work-order-service` as a new Spring Boot 3.3 microservice and implement five domains within it: Item Master CRUD, multi-level BOM authoring with recursive explosion, User-Defined Fields (via new `mes-udf-lib` shared library), BOM effectivity management, and Engineering Change Orders. A sixth sub-feature (AS5553 counterfeit fields) enriches the item master schema. All entities are org-scoped, Envers-audited, Kafka-evented, and secured via Keycloak JWT privileges registered at startup.

**Project Type**: REST microservice — one of 16 domain services in the Aurora MES monorepo

**Constraints**: BOM max depth configurable (`mes.bom.max-depth`, default 50); circular detection at line-create time; effectivity overlap rejection at service layer

**Scale/Scope**: Single-org per deployment in v1; `org_id` carried on all entities per Constitution §IX; multi-org is DEF-003 (deferred)

### Privilege Registration

`WorkOrderServiceApplication` implements `ApplicationListener<ApplicationReadyEvent>` and calls `PrivilegeRegistryClient.register()` on startup to POST:
```json
{
  "moduleName": "item-master",
  "privileges": [
    { "privilegeKey": "item-master:records:view",   "description": "View item master records" },
    { "privilegeKey": "item-master:records:manage", "description": "Create and update item master records" },
    { "privilegeKey": "item-master:bom:manage",     "description": "Author and release BOM revisions" },
    { "privilegeKey": "item-master:eco:manage",     "description": "Create and approve ECOs" },
    { "privilegeKey": "item-master:udf:manage",     "description": "Define and delete UDF fields" }
  ]
}
```

### Key Service-Layer Rules

- **BOM structural changes**: service rejects add/update/remove BOM line if `BillOfMaterials.status != DRAFT` (HTTP 409)
- **Circular reference**: before persisting a `BomLine`, service runs a CTE checking if `componentItemId` is an ancestor of `bomId.parentItemId`
- **Date effectivity overlap**: service queries existing lines for same `bomId + findNumber` and validates no date range intersection
- **Effectivity gap**: BOM explosion service checks for find numbers with no covering line for the requested `asOfDate` / `asOfUnit`
- **ECO immutability**: service rejects mutations to ECOs in APPROVED or IMPLEMENTED state (HTTP 409)
- **Concurrent ECO warning**: on ECO create, service checks for open ECOs on the same `affectedItemIds`; sets `concurrentEcoWarning = true` in response (non-blocking)
- **UDF validation**: `UdfValidator.validate(moduleKey, orgId, customFields)` is called on every item master create/patch; fails fast with 422 listing all missing/invalid fields

### Kafka Event Schema (JSON)

All events follow the pattern used by `lib-common-audit`:

```json
{
  "eventId": "uuid",
  "eventType": "ITEM_MASTER_CREATED | ITEM_MASTER_UPDATED | BOM_RELEASED | BOM_OBSOLETED | ECO_APPROVED | ECO_IMPLEMENTED",
  "entityType": "ItemMaster | BillOfMaterials | EngineeringChangeOrder",
  "entityId": "uuid",
  "orgId": "uuid",
  "actorId": "keycloak-sub",
  "occurredAt": "ISO-8601",
  "payload": { /* full entity DTO snapshot */ }
}
```
