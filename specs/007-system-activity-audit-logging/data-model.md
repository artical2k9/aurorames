# Data Model: System Activity & Audit Logging (MES-7)

## Schema Overview

All audit tables live in the PostgreSQL schema `audit`. The application DB role `audit_service` has SELECT + INSERT. No UPDATE or DELETE is ever granted at the application layer. Flyway migrations are run by a separate `audit_flyway` role with DDL rights.

---

## Table: `audit.audit_records`

Core immutable store for Kafka-published business events and Keycloak authentication events. Hibernate Envers entity mutations are stored in `_AUD` tables generated by Envers (see below), but may be projected into this table by the query API.

```sql
CREATE TABLE audit.audit_records (
    id              UUID         NOT NULL DEFAULT gen_random_uuid(),
    event_id        UUID         NOT NULL,                  -- deduplification key (from AuditEventMessage.eventId)
    event_type      VARCHAR(30)  NOT NULL,                  -- ENTITY_CHANGE | KAFKA_EVENT | AUTH_EVENT
    entity_type     VARCHAR(100) NOT NULL,                  -- e.g. 'WorkOrder', 'Material'
    entity_id       VARCHAR(100) NOT NULL,
    user_id         VARCHAR(100) NOT NULL,                  -- JWT sub claim, or 'system:<service-name>'
    service_source  VARCHAR(100) NOT NULL,                  -- publishing service name
    action          VARCHAR(20)  NOT NULL,                  -- CREATE | UPDATE | DELETE | PUBLISH | AUTH
    occurred_at     TIMESTAMPTZ  NOT NULL,                  -- UTC millisecond precision
    previous_state  JSONB,
    new_state       JSONB,
    checksum        VARCHAR(64)  NOT NULL,                  -- SHA-256 hex of canonical fields
    schema_version  SMALLINT     NOT NULL DEFAULT 1,
    tenant_id       UUID,                                   -- future multi-org row-level filtering
    CONSTRAINT pk_audit_records PRIMARY KEY (id),
    CONSTRAINT uq_audit_records_event_id UNIQUE (event_id)  -- idempotent consumer deduplication
);

CREATE INDEX idx_audit_records_entity ON audit.audit_records (entity_type, entity_id, occurred_at DESC);
CREATE INDEX idx_audit_records_user   ON audit.audit_records (user_id, occurred_at DESC);
CREATE INDEX idx_audit_records_time   ON audit.audit_records (occurred_at DESC);
CREATE INDEX idx_audit_records_tenant ON audit.audit_records (tenant_id, occurred_at DESC);
```

**Immutability enforcement (V002 migration)**:
```sql
REVOKE UPDATE, DELETE ON audit.audit_records FROM audit_service;
```

## Table: `audit.auth_audit_records`

Authentication and authorisation events from Keycloak (LOGIN, LOGOUT, LOGIN_ERROR, ROLE_MAPPING, etc.).

```sql
CREATE TABLE audit.auth_audit_records (
    id              UUID         NOT NULL DEFAULT gen_random_uuid(),
    event_id        UUID         NOT NULL,                  -- deduplification key
    event_type      VARCHAR(60)  NOT NULL,                  -- Keycloak EventType enum name
    user_id         VARCHAR(100),                           -- null for admin events without a user context
    client_id       VARCHAR(100),
    ip_address      VARCHAR(45),                            -- IPv4 or IPv6
    session_id      VARCHAR(100),
    realm_id        VARCHAR(100) NOT NULL,
    occurred_at     TIMESTAMPTZ  NOT NULL,
    details         JSONB,                                  -- Keycloak event.details map
    tenant_id       UUID,
    CONSTRAINT pk_auth_audit_records PRIMARY KEY (id),
    CONSTRAINT uq_auth_audit_records_event_id UNIQUE (event_id)
);

CREATE INDEX idx_auth_audit_user ON audit.auth_audit_records (user_id, occurred_at DESC);
CREATE INDEX idx_auth_audit_type ON audit.auth_audit_records (event_type, occurred_at DESC);
CREATE INDEX idx_auth_audit_time ON audit.auth_audit_records (occurred_at DESC);
```

## Hibernate Envers Revision Tables

Envers generates one `_AUD` table per `@Audited` entity. These tables are owned by each **domain service** (in their respective schemas) — not by audit-service. Audit-service queries them via a shared Envers configuration.

### Shared: `audit.mes_revisions` (custom RevisionEntity)

```sql
CREATE TABLE audit.mes_revisions (
    rev             INTEGER      NOT NULL GENERATED ALWAYS AS IDENTITY,
    rev_tstmp       BIGINT       NOT NULL,                  -- epoch millis
    user_id         VARCHAR(100) NOT NULL,
    service_source  VARCHAR(100) NOT NULL,
    CONSTRAINT pk_mes_revisions PRIMARY KEY (rev)
);
```

### Example: `work_order.work_orders_AUD` (generated by Envers per domain service)

```sql
-- Generated by Hibernate Envers for WorkOrder entity
-- (ValidityAuditStrategy: adds REVEND + REVEND_TSTMP for efficient point-in-time queries)
CREATE TABLE work_order.work_orders_aud (
    id              UUID         NOT NULL,
    rev             INTEGER      NOT NULL REFERENCES audit.mes_revisions(rev),
    revtype         SMALLINT     NOT NULL,                  -- 0=ADD, 1=MOD, 2=DEL
    revend          INTEGER      REFERENCES audit.mes_revisions(rev),
    revend_tstmp    BIGINT,
    -- entity fields (nullable, only populated when changed):
    order_number    VARCHAR(50),
    status          VARCHAR(30),
    org_id          UUID,
    -- ... other WorkOrder fields ...
    CONSTRAINT pk_work_orders_aud PRIMARY KEY (id, rev)
);
```

## JPA Entities (lib-common-audit)

### `AuditRecord.java`

```java
@Entity
@Table(schema = "audit", name = "audit_records")
@Immutable
public class AuditRecord {
    @Id UUID id;
    @Column(name = "event_id", nullable = false, unique = true) UUID eventId;
    @Column(name = "event_type")  String eventType;   // ENTITY_CHANGE | KAFKA_EVENT | AUTH_EVENT
    @Column(name = "entity_type") String entityType;
    @Column(name = "entity_id")   String entityId;
    @Column(name = "user_id")     String userId;
    @Column(name = "service_source") String serviceSource;
    @Column String action;
    @Column(name = "occurred_at") OffsetDateTime occurredAt;
    @Type(JsonBinaryType.class) @Column(name = "previous_state", columnDefinition = "jsonb") Map<String,Object> previousState;
    @Type(JsonBinaryType.class) @Column(name = "new_state",      columnDefinition = "jsonb") Map<String,Object> newState;
    @Column String checksum;
    @Column(name = "schema_version") int schemaVersion;
    @Column(name = "tenant_id") UUID tenantId;
}
```

## Kafka Message Schema (lib-common-events)

### `AuditEventMessage.java`

```java
public record AuditEventMessage(
    UUID    eventId,           // UUID v4 — deduplication key
    String  eventType,         // ENTITY_CHANGE | KAFKA_EVENT | AUTH_EVENT
    String  serviceSource,     // e.g. "work-order-service"
    String  entityType,        // e.g. "WorkOrder"
    String  entityId,          // entity PK as String
    String  userId,            // JWT sub, or "system:<service>"
    OffsetDateTime timestamp,
    String  action,            // CREATE | UPDATE | DELETE | PUBLISH | AUTH
    Map<String,Object> payload,
    int     schemaVersion      // 1 for v1; increment on breaking change
) {}
```

**Kafka topic**: `mes.audit.events`  
**Consumer group**: `audit-service-group`  
**Partition key**: `entityType + ":" + entityId` (ensures ordered delivery per entity)

## Entity Relationships

```
audit.mes_revisions (1) ←── (*) work_order.work_orders_AUD
                        ←── (*) quality.inspections_AUD
                        ←── (*) ncm.nonconformances_AUD
                        ... (one _AUD table per @Audited entity in each service schema)

audit.audit_records — standalone table for Kafka-sourced and auth events
audit.auth_audit_records — Keycloak authentication events

AuditEventMessage (Kafka) → consumed by audit-service → INSERT INTO audit.audit_records
KeycloakAuditSPI (Kafka)  → consumed by audit-service → INSERT INTO audit.auth_audit_records
```

## State Transitions

`AuditRecord.action` values and their sources:

| Action | Source | Description |
|---|---|---|
| `CREATE` | Envers (REVTYPE=0) or Kafka | Entity first persisted |
| `UPDATE` | Envers (REVTYPE=1) or Kafka | Entity field(s) changed |
| `DELETE` | Envers (REVTYPE=2) or Kafka | Entity removed |
| `PUBLISH` | Kafka only | Business event (no DB mutation; e.g. WorkOrder released to floor) |
| `AUTH`    | Keycloak SPI Kafka | Login, logout, role change |

## Validation Rules

- `event_id`: UUID, non-null, unique across `audit_records` and `auth_audit_records` separately.
- `occurred_at`: UTC only; client-provided timestamps are normalized to UTC on ingestion.
- `payload` / `previous_state` / `new_state`: truncated to 64 KB; a `payload_truncated: true` flag is added to the JSON if truncated.
- `user_id`: non-null; `"system:<service-name>"` when no JWT principal is available.
- `checksum`: exactly 64 hex characters (SHA-256).
- `schema_version`: 1 or 2 accepted in v1 (N-1 backward compatibility per R9).
